# Grupos de Dispositivos (Device Groups)

> **Nota:** Promovida para o núcleo (*core*) no Vulkan 1.1.
>
> - [SPV_KHR_device_group](https://htmlpreview.github.io/?https://github.com/KhronosGroup/SPIRV-Registry/blob/main/extensions/KHR/SPV_KHR_device_group.html)
> - [GLSL - GL_EXT_device_group](https://github.com/KhronosGroup/GLSL/blob/master/extensions/ext/GL_EXT_device_group.txt)

Os grupos de dispositivos (*device groups*) são uma forma de representar múltiplos dispositivos físicos (de um mesmo fabricante) como um único dispositivo lógico. Se, por exemplo, uma aplicação tiver duas GPUs idênticas conectadas por alguma interface de ponte (*bridge*) fornecida pelo fabricante em um único sistema, uma abordagem seria criar dois dispositivos lógicos no Vulkan. O problema é que existem limitações quanto ao que pode ser compartilhado e sincronizado entre dois objetos `VkDevice` — o que não é necessariamente ruim, mas há casos de uso em que uma aplicação pode querer combinar a memória entre duas GPUs.

Os *Device Groups* foram projetados para esse caso de uso, permitindo que uma aplicação crie "subdispositivos" (*sub-devices*) dentro de um único `VkDevice`. Com grupos de dispositivos, objetos como `VkCommandBuffer` e `VkQueue` não ficam vinculados a um único "subdispositivo"; em vez disso, o driver gerencia em qual dispositivo físico executá-los. Outro uso para grupos de dispositivos é um sistema alternativo de apresentação de quadros, no qual cada quadro é exibido por um "subdispositivo" diferente.

Existem duas extensões: `VK_KHR_device_group` e `VK_KHR_device_group_creation`. O motivo de existirem duas extensões separadas é que as extensões são classificadas como "extensões de nível de instância" (*instance level extensions*) ou "extensões de nível de dispositivo" (*device level extensions*). Como os grupos de dispositivos precisam interagir tanto com chamadas de nível de instância quanto de nível de dispositivo, duas extensões foram criadas. Há também uma extensão SPIR-V correspondente, [SPV_KHR_device_group](https://htmlpreview.github.io/?https://github.com/KhronosGroup/SPIRV-Registry/blob/main/extensions/KHR/SPV_KHR_device_group.html), que adiciona a capacidade `DeviceGroup` e um novo *built-in* `DeviceIndex` aos shaders, permitindo que eles controlem o que fazer para cada dispositivo lógico. Ao usar GLSL, há também a extensão [GL_EXT_device_group](https://github.com/KhronosGroup/GLSL/blob/master/extensions/ext/GL_EXT_device_group.txt), que introduz a variável *built-in* `highp int gl_DeviceIndex;` para todos os tipos de shader.
